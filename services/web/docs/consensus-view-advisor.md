# 컨센서스 뷰 어드바이저 (운영자 개인용)

목표: **집단 예측 컨센서스로 내 시장 뷰를 검증하고, 검증된 만큼만 실제 상장 상품(개별주·ETF·ETN)의 포지션으로
옮긴다.** 이 서비스의 처음 구상이다(운영자 2026-11-12) — 참여자들이 실제 돈을 건 확률은 솔직한 기대이고,
유동성 장세에서 그 기대는 시장 방향의 선행 지표다. 종목 DB와 리서치는 이것을 위해 만든 것이었다.

**운영자 개인용이다. 공개 서비스가 아니다**(운영자 지시 2026-11-12). 특정 상품에 방향을 붙여 보이는 화면은
`/terms`의 "특정 종목의 매매를 상담하지 않습니다"와 맞지 않는다. `.env`의 `VIEW_CHECK_ACCOUNT_KEYS`에 적은 계정만
쓰고 다른 계정에는 화면에도 API에도 드러나지 않는다. 공개로 넓히려면 약관·방침부터 다시 정한다.

항목이 끝나면 지우고, 전부 끝나면 이 파일째 지운다. 끝낸 것은 git 이력에 있다.

## 1. 지금 있는 것 (1단계, 2026-11-12)

`/research`의 "컨센서스로 뷰 검증"(`services/web/viewcheck/`, `llm/viewcheck.py`, `POST /api/research/view`).
뷰는 리서치 주제와 같은 글이고 동의도 리서치의 것을 쓴다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 전제 나누기 | 모델 | 뷰를 "무엇이 어떻게 된다" 전제(최대 5)로 나누고 전제마다 짧은 검색어를 낸다 |
| 찾기 | 서버 | 검색어를 질의응답과 같은 1차 검색에 넣는다. 참여가 얇거나 72시간 안에 끝나는 질문은 뺀다. 뷰와 무관하게 참여가 몰린 경제·지정학 질문 8개를 따로 붙인다 |
| 판정 | 모델 | 전제마다 받침·어긋남·엇갈림·확인할 질문 없음, 근거 질문 번호, 숫자 없는 해설. 다듬은 뷰, 뷰가 놓친 신호 |
| 숫자 | 서버 | 확률은 detail 값 그대로 붙인다. 모델 입력에는 등급만 간다 |
| 포지션 | 모델 | 다듬은 뷰와 판정을 보고 상품 표(`viewcheck/instruments.py`, ETF·ETN 127개)와 관심종목에서 고른다 |
| 규칙 | 서버 | 표 밖 상품은 버린다. 한 주제에 하나. 근거 전제가 전부 어긋난 확대·축소는 지켜보기로 내린다. 레버리지·역방향·ETN 주의 문구, 같은 성격의 다른 상품을 붙인다 |
| 이동 | 서버 | 화면을 열 때마다 검증 때 보인 선택지의 지금 확률을 읽어 차이를 보인다(LLM 없음). 10%p 넘게 움직였으면 다시 검증하라고 알린다 |

설계의 근거가 된 실측(2026-11-11~12, 운영 수집분):

- 뷰 문장을 통째로 검색하면 후보가 0건이다(낱말 절반이 맞아야 후보). 그래서 전제 단계가 검색어를 낸다.
- 기본 모델(qwen3-30b)은 방향을 틀렸다 — "금리가 오른다"에서 장기 국채 비중 확대를 냈다. gpt-oss-120b는 국채 역방향·주식
  축소를 냈다. 이 기능만 `VIEW_CHECK_MODEL`을 쓴다. deepseek-v4.1-flash는 글이 더 낫지만 네 번 중 한 번이 출력
  상한에서 끊겼고 비용이 세 배였다.
- gpt-oss-120b도 드물게 같은 문장을 되풀이하며 상한까지 쓴다. 상한을 실측의 두 배로 낮추고, 끊기면 한 번 다시 부른다.
- 한 번에 1~5분, 1,000 Neurons 안팎(약 0.011달러). 계정 하루 10회·서버 하루 100회.
- 모델이 사다리 질문("↓ $85")의 등급을 거꾸로 읽은 해설이 있었다. 화면이 원문 제목·선택지·확률을 해설 옆에 늘 보이는
  이유다 — 판단은 숫자로 한다.

## 2. 남은 것

1. **성적표** — 컨센서스가 정말 선행 지표인지 이 서비스의 기록으로 잰다. 검증마다 전제·근거 질문·그때 확률·포지션을
   남기고, 질문이 정산된 뒤 (a) 컨센서스가 맞았는지 (b) 뷰가 맞았는지 (c) 포지션 상품이 그 사이 어느 쪽으로 갔는지를
   본다. (c)는 시세가 필요하다 — 웹은 외부 시세를 부르지 않으므로 봇이 구워 주는 파일이 먼저다. 지금은 최근 검증 한 건만
   남고 정산 결과를 읽는 곳도 없다(수집분은 열린 질문만 담는다).
2. **매일 지켜보기** — 뷰를 받치던 컨센서스가 크게 움직인 날을 화면을 열지 않아도 알린다. "오늘 점검"
   (`portfolio/watch.py`)이나 텔레그램 알림에 싣는다. 이동 계산(`service.drift`)은 이미 LLM 없이 돈다.
3. **리서치와 잇기** — 지금은 같은 화면의 두 버튼이다. 뉴스 리서치(개별주 후보)가 다듬은 뷰와 판정을 입력으로 받고,
   포지션 단계가 리서치의 종목 제안을 후보로 받게 한다. 리서치 프롬프트는 봇과 웹이 같은 사본이라 양쪽을 같이 고친다.
4. **상품 표 넓히기** — 한국 상품은 숫자 여섯 자리 코드만 실었다(관심종목 정규 코드). 2024년 이후 상장분의 영문 섞인
   코드와 중국·홍콩 상장 ETF는 없다. 표가 낡았는지는 `tests/viewcheck_instruments_probe.py`로 본다(ETN은 만기가 있다).
5. **보유 자산 반영** — 포지션 단계는 관심종목만 본다. 자산을 외부 AI로 보내지 않는 원칙을 지키면서 "이미 가진 것"을
   반영하려면 서버가 포지션과 보유 종목을 대조해 붙이는 길이 있다(모델에는 보내지 않는다).
