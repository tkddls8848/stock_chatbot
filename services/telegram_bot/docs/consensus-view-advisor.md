# 컨센서스 뷰 어드바이저 (운영자 개인용)

목표: **집단 예측 컨센서스로 내 시장 뷰를 검증하고, 검증된 만큼만 실제 상장 상품(개별주·ETF·ETN)의 포지션으로
옮긴다.** 이 서비스의 처음 구상이다(운영자 2026-11-12) — 참여자들이 실제 돈을 건 확률은 솔직한 기대이고,
유동성 장세에서 그 기대는 시장 방향의 선행 지표다. 종목 DB와 리서치는 이것을 위해 만든 것이었다.

**운영자 개인용이다. 공개 서비스가 아니다**(운영자 지시 2026-11-12). 특정 상품에 방향을 붙여 보이는 기능은
웹 `/terms`의 "특정 종목의 매매를 상담하지 않습니다"와 맞지 않는다. 그래서 **공개 웹이 아니라 운영자만 보는
텔레그램 방에 둔다**(`/view`). 처음에는 웹 `/research`에 계정 제한으로 붙였다가 같은 날 옮겼다 — 웹에는 이 기능의
라우트·화면·설정이 없다. 공개로 넓히려면 약관·방침부터 다시 정한다.

항목이 끝나면 지우고, 전부 끝나면 이 파일째 지운다. 끝낸 것은 git 이력에 있다.

## 1. 지금 있는 것 (1단계, 2026-11-12)

텔레그램 `/view`(`services/telegram_bot/features/view_check/`, `llm/view_check.py`).

| 명령 | 하는 일 |
|---|---|
| `/view 뷰 문장` | 검증을 시작한다. 1~5분 뒤 결과를 보낸다 |
| `/view` | 최근 검증과 그 뒤 컨센서스 이동(LLM 없음) |
| `/view run` | 최근 뷰로 다시 검증 |

봇은 웹 코드를 import하지 않는다. 컨센서스는 웹의 공개 GET API(`/api/forecast/events`, `/api/forecast/events/{id}`)로
읽는다(`consensus.py`).

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 전제 나누기 | 모델 | 뷰를 "무엇이 어떻게 된다" 전제(최대 5)로 나누고 전제마다 짧은 검색어를 낸다 |
| 찾기 | 봇 | 검색어를 웹의 자연어 검색(`/api/forecast/events?q=`)에 넣는다. 참여가 얇거나 72시간 안에 끝나는 질문은 뺀다. 뷰와 무관하게 참여가 몰린 경제·지정학·복합 분야 질문 6개(분야마다 최대 3)를 따로 붙인다 |
| 판정 | 모델 | 전제마다 받침·어긋남·엇갈림·확인할 질문 없음, 근거 질문 번호, 숫자 없는 해설. 다듬은 뷰, 뷰가 놓친 신호 |
| 숫자 | 봇 | 확률은 웹이 준 값 그대로 붙인다. 모델 입력에는 등급만 간다 |
| 포지션 | 모델 | 다듬은 뷰와 판정을 보고 상품 표(`instruments.py`, ETF·ETN 127개)와 봇 관심종목(`storage/portfolio/watchlist.json`)에서 고른다 |
| 규칙 | 봇 | 표 밖 상품은 버린다. 한 주제에 하나. 근거 전제가 전부 어긋난 확대·축소는 지켜보기로 내린다. 레버리지·역방향·ETN 주의 문구, 같은 성격의 다른 상품을 붙인다 |
| 이동 | 봇 | `/view`를 보낼 때마다 검증 때 보인 선택지의 지금 확률을 읽어 차이를 적는다(LLM 없음). 10%p 넘게 움직였으면 다시 검증하라고 알린다 |

설계의 근거가 된 실측(2026-11-11~12, 운영 수집분):

- 뷰 문장을 통째로 검색하면 후보가 0건이다(낱말 절반이 맞아야 후보). 그래서 전제 단계가 검색어를 낸다.
- **비용을 가장 적게 쓰는 쪽으로 정한다**(운영자 지시 2026-11-12). Workers AI는 유료 요금제에도 추가 포함분이 없다 —
  하루 10,000 Neurons 무료, 넘으면 1,000당 0.011달러이고, 검색 주석 one-shot만으로 하루 4,000을 쓴다.
- 모델별 실측(같은 뷰, 운영 수집분):

  | 구성 | 한 번에 | 결과 |
  |---|---|---|
  | 기본 모델(qwen3-30b), 추론 끔 | 130 Neurons | 방향을 틀린다("금리가 오른다" → 장기 국채 확대) |
  | 기본 모델, 판정·포지션만 추론 켬 | 225~310 | 여섯 번 중 세 번 틀림(국채 역방향 축소, "동결"을 받침으로 오독, "유가 안정" → 원유 확대) |
  | gpt-oss-20b | 230~510 | 세 번 중 한 번 영어로 답하며 틀림, 한 번 포지션 단계 끊김 |
  | **gpt-oss-120b(판정·포지션만)** | **800~1,000** | 일곱 번 모두 방향이 맞음. 드물게 같은 문장을 되풀이하다 상한에서 끊김 |
  | deepseek-v4.1-flash | 2,000~2,800 | 글이 가장 낫지만 네 번 중 한 번 끊김 |

  mistral-small은 방향이 틀렸고 gemma-4·glm-5.3-flash는 추론이 출력 상한을 다 썼다.
- 그래서 전제 나누기는 기본 모델, 판정·포지션만 gpt-oss-120b다. 입력 토큰이 비용의 대부분이라 상품 표를 한 줄씩 주고
  후보 수를 줄였다. 글 하나가 검사에 걸린 것으로는 다시 부르지 않고, 응답을 통째로 못 쓸 때만 한 번 다시 부른다.
- 한 번에 1~5분, 약 0.01달러. 하루 10회(실패도 센다), 한 번에 하나. 결과 끝에 그 검증이 쓴 Neurons를 적는다
  (봇 경로 첫 실측 2026-11-12: 106초, 945 Neurons).
- 모델이 사다리 질문("↓ $85")의 등급을 거꾸로 읽은 해설이 있었다. 메시지가 원문 제목·선택지·확률을 해설 옆에 늘 적는
  이유다 — 판단은 숫자로 한다.

## 2. 남은 것

1. **성적표** — 컨센서스가 정말 선행 지표인지 이 서비스의 기록으로 잰다. 검증마다 전제·근거 질문·그때 확률·포지션을
   남기고, 질문이 정산된 뒤 (a) 컨센서스가 맞았는지 (b) 뷰가 맞았는지 (c) 포지션 상품이 그 사이 어느 쪽으로 갔는지를
   본다. (c)는 시세가 필요하다 — 봇의 시세(`stocks/quotes.py`)는 개별주용이라 ETF·ETN 시세부터 확인한다. 지금은 최근
   검증 한 건만 남고 정산 결과를 읽는 곳도 없다(웹 수집분은 열린 질문만 담는다).
2. **매일 지켜보기** — 뷰를 받치던 컨센서스가 크게 움직인 날을 `/view`를 보내지 않아도 알린다. 예약 작업 하나가
   이동 계산(`service.drift`·`moved`, LLM 없음)을 돌려 넘었을 때만 한 통 보낸다. 같은 이동을 매일 되풀이해 알리지 않게
   알린 값을 기억해야 한다.
3. **리서치와 잇기** — 지금은 `/view`와 `/research`가 따로 돈다. 뉴스 리서치(개별주 후보)가 다듬은 뷰와 판정을
   입력으로 받고, 포지션 단계가 리서치의 종목 제안을 후보로 받게 한다. 기능끼리 import하지 않으므로 다듬은 뷰를
   상태 파일로 넘긴다. 리서치 프롬프트는 봇과 웹이 같은 사본이라 양쪽을 같이 고친다.
4. **상품 표 넓히기** — 한국 상품은 숫자 여섯 자리 코드만 실었다. 2024년 이후 상장분의 영문 섞인 코드와 중국·홍콩
   상장 ETF는 없다. 표가 낡았는지는 `tests/view_check_instruments_probe.py`로 본다(ETN은 만기가 있다).
5. **보유 자산 반영** — 포지션 단계는 관심종목만 본다. 보유 자산은 웹 계정 저장소에 있고 봇은 읽지 않는다. "이미 가진
   것"을 반영하려면 그 경계부터 정한다(자산은 외부 AI로 보내지 않는다).
6. **포지션 상품 지켜보기** — 웹에 있던 "관심종목에 담기"는 옮기지 않았다. 봇 관심종목은 뉴스 종목명 매칭·시세·브리핑의
   입력이라 ETF를 넣으면 그쪽이 흔들린다. 포지션으로 받은 상품을 따로 적어 두고 시세를 보이려면 자리를 새로 만든다.
